# Развёртывание

1. Сохраните резервную копию текущего document root и серверной конфигурации.
2. Загрузите содержимое `site/` в корень сайта. Обязательно скопируйте `.htaccess`, `404.html` и всю папку `assets/`. Не загружайте original/, source/ и reports/ в публичный корень.
3. Нужен Apache 2.4 с mod_rewrite, mod_dir, mod_mime, разрешённым `AllowOverride All` для каталога сайта. Конфигурация не предназначена для Nginx без переноса правил. Для HTTP и www должны существовать виртуальные хосты; HTTPS-зеркалу www нужен действующий TLS-сертификат до выполнения 301.
4. При прямом TLS Apache использует `%{HTTPS}`. Если TLS завершается на reverse proxy, proxy обязан заменять `X-Forwarded-Proto`, не передавать клиентский заголовок без проверки и закрывать прямой доступ к backend. В поставленном .htaccess `X-Forwarded-Proto: https` считается подтверждением TLS. Если доверенного proxy нет, удалите условие по X-Forwarded-Proto и проверяйте только HTTPS. Уточните эту схему у администратора до установки, чтобы избежать циклов или возможности обхода HTTPS-редиректа.
5. Сбросьте CDN/серверный кэш изменённых HTML и assets/site-app.js. Старый index-DN2BKFX8.js больше не используется.
6. Проверьте на действующем домене: HTTP/www/index.html/адрес без слеша дают один 301 на https://5masters.ru с конечным путём; все URL sitemap отвечают 200; неизвестный адрес — 404; robots и sitemap доступны. В адресах со слешем, запросами и кириллицей не должно появляться двойное кодирование.
7. Проверьте в браузере телефон, фактическое открытие нужного чата MAX, /ceny/ → калькулятор, метатеги после внутренних переходов. В кабинете Метрики проверьте счётчик 113756817 и нужные цели. Локальные тесты не подтверждают получение событий Яндексом.
8. Сверьте данные с владельцем по REPORT.md. Для условных страниц портфолио и контактов опубликованы временные метатеги. После получения подтверждений внесите данные в source/, восстановите точные согласованные формулировки и заново выполните генерацию.

Для отката восстановите весь предыдущий document root, включая .htaccess и старые assets. Избирательное смешивание HTML и JS двух версий может вызвать ошибки гидратации.

# Воспроизведение

Скрипты используют Python 3 + beautifulsoup4 и Node.js + playwright-core, установленный Chromium. Скрипты передаются для воспроизведения преобразования поставленной сборки; исходников приложения в архиве нет.

Из каталога, содержащего work/ с папками original/, source/, site/, reports/:

```
python -m venv work/venv
work/venv/bin/pip install beautifulsoup4==4.15.0
npm install --no-save playwright-core@1.62.1
work/venv/bin/python work/source/build.py
```

Затем запустите Apache на 127.0.0.1:8090 с document root work/site и AllowOverride All. Скрипты тестирования передают Host: 5masters.ru и X-Forwarded-Proto: https только локальному тестовому серверу; этот заголовок не заменяет проверку реального HTTPS.

```
node work/source/prerender.mjs
work/venv/bin/python work/source/apply-snapshots.py
work/venv/bin/python work/source/validate.py
node work/source/browser-checks.mjs
node --check work/site/assets/site-app.js
```

Для совместимости со скриптами архив содержит каталог work/. Путь к Chromium в тестовых скриптах — /usr/bin/chromium; при необходимости измените его. Порт 8090 и адрес тестового Apache можно адаптировать к своей среде. Содержимое site/ уже готово: повторять генерацию для обычной загрузки не требуется.
